# Q-RADAR 대장 재분석 도구 (`migrate_tool/reanalyze_ledger/`) — 2026-09-16 신설 · 2026-10-16 현행

현재 프롬프트·방어망(`pipeline/brain.py`)으로 대장의 지정 행을 **다시 분석하고, 결과를 엑셀로 먼저 받아 사람이 승인한 행만** 시트에 반영합니다.
분석 로직은 여기 없고 core(scraper·brain·certs)를 그대로 부릅니다. 시트에 쓰는 코드는 `apply.py` 한 곳뿐입니다.

**용도** — 규칙(프롬프트·방어망)이 바뀌었을 때 과거 분석분을 같은 기준으로 **일괄 교정**하는 것. 매일 돌리는 도구가 아닙니다.
운영 배치(매일 새벽)는 사람 승인 없이 기록되므로, 거기서 틀린 것은 brain에 규칙을 박아 줄이고, 여기서는 그 규칙으로 과거분을 따라잡습니다.

## 준비 (1회)
1. `env.example`의 항목을 **레포 루트 `local_run/local.env`**에 채우기, 같은 폴더에 `gcp-key.json`(둘 다 깃허브 금지). 이 폴더에는 `.env`·키 파일을 두지 않습니다('26. 10. 13. 열쇠 단일화).
2. 로컬 백필 때 쓰던 파이썬 환경(hrdk-law-core 설치됨)에서, **국내 IP**로 실행.
3. `local.env`에 `LLM_MODEL=gemini-3.8-flash`, `LLM_THINKING_LEVEL=medium`(운영 yml과 동일) — 없으면 run이 물어봅니다.

## 실행 — `start.py`를 ▶ 버튼으로
```
[1] 대상 선정 (scan · 시트 읽기만)  → 화면에서 선택: 1 대장 전체 / 2 이상건 목록 xlsx / 3 MST_ID 목록 txt
[2] 재분석 실행 (run · 시트 읽기만) → "몇 건만?"(엔터=전량) → "캐시된 건도 다시?"(엔터=재사용)
[3] 시트 반영 (apply · 미리보기 → '반영' 입력 시에만 기록)
[4] 산출물 폴더 열기 (work/)
```
명령줄 인자는 필요 없습니다(명령줄 옵션은 아래 표). `#`으로 시작하는 줄은 MST_ID 목록 txt에서 주석으로 무시됩니다.

## 3단계

| 단계 | 하는 일 | 산출 | 시트 |
|---|---|---|---|
| 1 scan | 대장에서 대상 행 선정, MST_ID 중복·시행일자 빈칸 점검 | `work/대상목록_날짜.xlsx` (대상목록·시행일자별·누락) | 읽기만 |
| 2 run | 시행일자별로 법제처 **현행** 목록에서 원문 재수집 → 그날 목록에 없는 옛 판본(이후 재개정된 법령)은 **연혁(eflaw)**에서 그 시행일자 판본 수집 → 현재 프롬프트·방어망으로 분석 | `work/재분석_대조_날짜.xlsx` (같은 이름이 있으면 `_2`, `_3`…) | 읽기만 |

| 3 apply | 승인 O 행만 MST_ID로 행을 다시 찾아 **분석 20칸**만 기록. 백업 탭 생성 → 기록 → 검산 | 백업 탭 `백업_국가기술자격 관련법령_날짜_시각` | **쓰기** |

### 대조 엑셀 열 읽는 법
| 열 | 뜻 |
|---|---|
| 상태 · 변경필드수 · 핵심변경 | 성공/실패, 바뀐 칸 수, 핵심 판정 칸의 구→신 |
| **추천 · 추천사유** | 기계가 먼저 거른 결과. `O 추천`(핵심 판정이 바뀜·근거 있음) / `O 추천(소폭)`(종목 추가·근거조문 변경뿐) / `O 추천(정리)`(구 분석이 스스로 검토필요 O로 신고했던 행이 깨끗해졌거나, 삭제된 종목이 원문에 글자로도·등급 통칭 문구로도 없는 과잉추론 정리) / `미반영`(핵심 판정·종목·근거조문 동일, 해설만 다름) / **`사람 판단`**(삭제된 종목이 원문에 글자로 있음·분야 확장분일 수 있음·우대 O→빈칸·연관도 하향·신 검토필요 O·연관높음인데 상세 빈칸). 승인 O는 **사람이 찍습니다** |
| 자동보강(R6·R7) | brain 방어망이 원문 글자 대조로 **자동 추가**한 종목·등급 통칭 확장 내역(시트에는 상세 분석 결과 끝 "※" 메모로 들어감) |
| 원문미출현_종목 | 신 종목 중 원문에 글자 그대로 없는 것(등급·분야 문언에서 끌어낸 종목이면 정상, 엉뚱한 종목이면 과잉 추론 의심) — 정보용 |
| 판본출처 | 빈칸 = 그날 현행 목록 / 값 있음 = 연혁에서 받은 판본(MST·공포번호) |
| 소요초 · 원문글자수 · 사전밖_제외 | 분석 시간, 모델에 넣은 글자 수(상한 80만 자), 사전에 없어 뺀 명칭 |
| 구_… / 신_… | 24칸 구·신 값. **`신_` 칸을 엑셀에서 고치면 그 값이 기록됩니다**(예: 자동보강 종목을 손보고 승인) |
| 변경요약 시트 | 건수·열별 변경 분포·추천 집계·모델·프롬프트 버전 |
| 실패 시트 | 단계(원문/분석)와 사유. 한 건의 예외는 그 건만 실패로 남고 다음 법령으로 진행, traceback은 `work/오류로그_날짜.txt` |

### 캐시와 프롬프트 버전
- 원문은 `work/cache/laws_날짜.json`, 결과는 `work/cache/result_MST_ID.json`. 중단 후 다시 돌리면 캐시부터 이어갑니다(법제처·AI 재호출 없음).
- 결과 캐시에 `brain.PROMPT_VERSION`을 기록합니다. **프롬프트·방어망 규칙이 바뀌어 버전이 오르면 자동으로 다시 분석**하고, 같으면 재사용합니다. 반복 일치율을 재려면 [2]에서 "다시 분석"에 y.
- 비교는 종목·근거조문의 **순서를 무시**합니다(순서만 바뀐 칸은 변경으로 세지 않고, apply도 쓰지 않음).

### 명령줄 옵션(필요할 때)
`scan.py --all | --targets 이상건.xlsx [--sheet 시트명] | --ids 목록.txt [--local 대장.xlsx]` ·
`run.py [--targets 대상목록.xlsx] [--limit N] [--force] [--mock]` ·
`apply.py [--file 대조.xlsx] [--commit] [--local 대장.xlsx] [--force] [--no-backup]`
`--mock`은 법제처·AI 호출 없이 엑셀 생성만 확인하는 테스트(파일명에 `_MOCK`), `--local`은 구글 시트 대신 로컬 xlsx(쓰기 불가).

## 안전장치
- 고정 키 4열(MST_ID·시행일자·소관부처·법령명)은 절대 덮어쓰지 않음. 분석 산출 20열만 갱신.
- 승인 빈칸 = 미반영(기본). 대조 이후 시트 값이 바뀐 행(표류)은 건너뜀(`--force`로만 덮어씀).
- apply는 MST_ID로 행을 다시 찾아 쓰므로 시트가 중간에 정렬돼도 안전. 대장에 MST_ID 중복이 있으면 scan이 경고하고 apply는 중단.
- 로컬 xlsx(`--local`)로 본 미리보기에서는 '반영'을 묻지 않습니다(시트와 다른 파일을 보고 쓰면 안 되므로).

## 전수 재분석 절차(2026. 10. 기준)
1. [1] → 1(대장 전체 2,199건) → [2] → "몇 건만" 700(또는 엔터) → 엔터. 법령당 평균 약 33초, 전수 약 20시간(밤에, 나눠서). 중간에 Ctrl+C 해도 다음 [2]가 캐시부터 이어감.
2. 끝난 대조 엑셀에서 추천이 `O 추천…`인 행은 승인 O 일괄, `사람 판단` 행만 사유를 보고 결정(전수 2,199행 기준 약 400~600행 — 보강안 복사·등급 통칭 판단·"맞네" 확인·진짜 읽기·분야 확장 확인의 다섯 종류).
3. [3] 두 번: 일괄 승인분 먼저 → 사람 판단분 검토 후(이미 쓴 행은 표류 감지로 자동 건너뜀).

# HRDK Q-RADAR — AI 기반 국가기술자격 관계법령 모니터링

> **법령 조회는 누구나 할 수 있습니다. 진짜 중요한 건 체계화된 분석과 DB 축적.**
> 매일 새벽, 대한민국의 제·개정 법령 전수를 자동 수집하고 AI가 **국가기술자격과의
> 관련성·우대사항**을 분석하여 대국민 사이트와 월간 브리핑으로 내보내는
> 한국산업인력공단 자격품질관리국 자격품질기획부 추진과제입니다.

**🔗 라이브: [자격증 법령 네비게이터](https://gjtjdwns1008-dev.github.io/hrdk-q-radar/)** — 4개 화면, 매일 4회 자동 갱신(06:00 · 08:30 · 14:00 · 20:00 KST)

## 왜 만들었나

법령은 한 해 **5,192건**('25년 실측) 바뀌지만, 담당자 수작업 검토는 그 **약 절반**만
관측할 수 있었습니다. 법이 바뀌어 특정 자격자의 채용이 의무화되어도 정작 그 자격증을
가진 국민은 모르고 지나치는 "정보의 사각지대"가 생깁니다.
Q-RADAR는 그 분석을 AI가 매일 대신합니다 — **"어떤 자격증에, 어떤 이득(의무고용·직무권한부여·
인사우대·시험면제)이 생겼는지"**, 근거 조문과 현재 채용 건수까지.

## 라이브 화면 (4개)

| 화면 | 내용 |
|---|---|
| **법령 모니터링 총괄현황** | 날짜별 수집·검토·우대 집계 — 수치를 누르면 그날의 법령 목록·상세 분석까지, 수집 실패일은 사유와 함께 표기 |
| **자격증 활용도 모니터링** | 제·개정 법령별 노동시장 활용도 분석 — 소관부처 필터·종목 칩 클릭 검색·결과 CSV |
| **자격증별 우대사항** | 종목 카드 → 우대 법령·성격·근거 조문 — 직능연 유형화 승계 5종 분류 + 자체 Track1(정책)·Track2(구직자) 분류, 중대재해처벌법 대상 표기 |
| **월간 이슈브리핑** | 자동 생성 + 담당자 검토 후 게시되는 심층 해설 (게시 = 검토자의 커밋) |

모든 화면 상단에 **AI 분석물 고지 배너**, 총괄현황에 **신뢰 카운터**(누적 검토·우대 축적·임의 폐기 0건) 상시 노출.
같은 대장은 공단 **Q-Page**(종목별 통계·우대법령 통합 페이지)에 우대법령 피드로도 공급됩니다(`migrate_tool/pref_export`).

## 통제된 AI — 이 저장소의 진짜 주제

AI는 **분석**하고, 코드는 **대조**하고, 사람은 **판단**합니다. 모델이 바뀌어도 아래는 코드에 남습니다.

- **환각 차단** — 종목 사전(541종) 전량 대조 + 옛 명칭 변환(252건): "이 목록 안에서만"
- **과잉추론 차단** — '행정규제의 직접적 명시' 판정 규칙(700여 건 오판 사건의 유산) + **타 법령 자격·인력만 인용한 조문은 우대 아님**(V27, '26. 10.): 「산림기술 진흥법」의 산림기술자처럼 다른 법령이 정한 인력만 인용하면 단순관련·종목 빈칸
- **글자 대조 교정**(V27.4~, '26. 10. 16.) — 모델은 "조문·별표에 있는 종목은 전부 적으라"는 지시를 두 번 돌려도 똑같이 빠뜨렸습니다(복어 조리 자격, 별표의 소방설비기사). 그래서 프롬프트가 아니라 코드가 고칩니다: 사전 종목명이 원문에 **글자 그대로** 있는데 결과에 없으면 자동 추가(R7), '변호사, 변리사, 공인회계사 또는 **기술사**의 자격'처럼 전문직 나열 속 등급 통칭은 그 등급 전체로 확장(R6, 전수 문구조사로 확인된 두 꼴만). 교정 내역은 상세 분석 결과 끝에 "※ 원문 대조로 추가" 메모로 남습니다. 방어망은 **종목만** 고치고 판정(연관도·우대여부·분류)은 건드리지 않습니다
- **검토필요 = 모델 자신의 불확실 신고** — 별표 파일 미확인, 표준 분류값 이탈, 사전 밖 명칭, 해석 불확실(R1~R5). 기계 대조로 알 수 있는 것은 신호 대신 교정하므로 담당자가 매일 재확인하는 과정은 없습니다
- **회귀 검증** — 프롬프트·방어망을 바꾸면 시범 20건(어제 결과와 1:1) → 표본 98건 → 같은 입력 반복(일치율)으로 확인한 뒤 반영. V27 개정에서 "등급 전체를 나열하라"는 강조 문구가 오히려 엉뚱한 분야까지 늘리고 흔들림을 키우는 것을 숫자로 확인해 철회했습니다
- **무손실 원칙** — 어떤 실패에도 법령을 조용히 버리지 않음. 한 건의 예외는 그 건만 실패로 남기고 다음 법령으로

프롬프트 개정 이력 V1~**V27.5**(`pipeline/brain.py`의 `PROMPT_VERSION`). 장애 대응은 "관측 → 반증 → 확정 → 방어"의 수사 방법론으로
전 과정 문서화 — 별표 705개 대량 수집 마비(연결 재사용으로 수 시간 → 194초), 서식 수천 개 다운로드 150분 초과(파일 상한), 조문 절단으로 인한 자격 조문 누락(상한 확대 + 자격 단어 없는 조문부터 생략).

## 재분석 도구 — 규칙이 바뀌면 과거분을 다시

`migrate_tool/reanalyze_ledger/` · Python ▶ 버튼으로 3단계(대상 선정 → 재분석 → 미리보기·'반영' 입력 시 기록) · 운영 배치와 분리된 로컬 도구

- 쌓인 검토필요 사례로 규칙을 재정립한 뒤 **과거 분석분을 시트에 일괄 교정**하기 위한 것(매일 돌리는 도구가 아님)
- 재개정된 법령의 옛 판본은 법제처 **연혁(eflaw)** 에서 그 시행일자 판본을 받아 분석
- 결과 캐시에 프롬프트 버전을 기록 — 규칙이 바뀌면 자동으로 다시 분석, 같으면 재사용(법제처·AI 재호출 0)
- 대조 엑셀: 구·신 24칸 비교, 종목·근거조문은 순서 무시, **추천** 열(핵심 판정 동일 → O 추천 / 삭제된 종목이 원문에 글자로 있음·우대 소멸·연관도 하향 → 사람 판단 / 과잉추론 정리 → O 추천(정리)) — 승인 O는 사람이 찍고, 기록은 백업 탭 생성 → 20개 분석 칸 쓰기 → 검산 순
- 함께 쓰는 로컬 도구: `문구조사.py`(등급 통칭 문구 전수조사 — '기사 이상의 자격'류 변형 분류), `방어망_재적용_점검.py`(방어망 변경을 AI 호출 없이 캐시로 미리 확인)

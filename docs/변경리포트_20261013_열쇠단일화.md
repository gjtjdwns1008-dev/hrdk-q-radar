# 변경리포트 — 로컬 열쇠 파일 단일화 + 변수 이름을 깃허브 시크릿과 일치
2026-10-13 · HRDK Q-RADAR · migrate_tool 전용 (운영 배치·네비게이터·GitHub Actions 무변경) · 1차(단일화)+2차(명칭 일치) 누적

## 1. 배경
- 로컬 PC에 열쇠 파일(.env·gcp-key.json)이 세 곳에 복사돼 있었다:
  `local_run/`, `migrate_tool/local_run/`(바이트 동일 복사본), `migrate_tool/.env`+`migrate_tool/gcp-key.json`.
- 원인은 코드 구조: migrate_tool 도구들이 **각자 자기 폴더**의 `.env`·`gcp-key.json`을 읽도록 되어 있었다
  (본체 스크립트 5종 각자 로더 + backfill_usage 공용 로더, reanalyze_ledger/common.py, pref_export/run_export_local.py).
  파일명도 `local.env`(운영 로컬 실행기) vs `.env`(도구)로 달랐다.
- 열쇠 4종 교체를 앞두고 복사본을 없애지 않으면, 교체 뒤에도 옛 열쇠가 PC에 남는다.

## 2. 결정
- **단일 위치 = `<레포 루트>/local_run/local.env` + `<레포 루트>/local_run/gcp-key.json`**
  (운영 로컬 실행기 run_today.py의 본거지. 루트 .gitignore의 `*.env`, `gcp*.json` 규칙으로 커밋 차단됨.)
- migrate_tool의 모든 도구는 이 두 파일만 읽는다. `migrate_tool/.env`, `migrate_tool/gcp-key.json`,
  `migrate_tool/local_run/`, `reanalyze_ledger/.env`, `pref_export/.env`는 더 이상 읽지 않는다.
- **(2차) 시트 변수 이름을 깃허브 시크릿과 동일하게**: migrate_tool이 쓰던 `QRADAR_SHEET` → `GOOGLE_SHEET_URL`.
  이로써 local.env에 적는 이름 = Actions Secrets 이름(LAW_API_KEY · GEMINI_API_KEY · GCP_SERVICE_ACCOUNT_JSON(파일로 대체) ·
  GOOGLE_SHEET_URL · WORKNET_API_KEY · WEBHOOK_URL · BRIEFING_WEBHOOK_URL)이 된다. 구 시트 두 개(MONITOR_SHEET·RADAR_SHEET)는
  시크릿이 없는 일회성 이관 도구 전용이라 이름 그대로 두되 평소엔 적지 않는다.

## 3. 조치 내역 (코드)
각 파일 상단, `HERE = Path(__file__).resolve().parent` 바로 아래에 같은 세 줄을 넣고
`HERE / ".env"` → `ENV_FILE`, `HERE / "gcp-key.json"` → `KEY_FILE` 로 바꿨다. 로직은 그대로.

```python
LOCAL_RUN = HERE.parent / "local_run"      # migrate_tool/ 바로 아래 스크립트 (REPO 변수가 있으면 REPO / "local_run")
# 하위 폴더(reanalyze_ledger/, pref_export/)는 HERE.parent.parent / "local_run"
ENV_FILE = LOCAL_RUN / "local.env"
KEY_FILE = LOCAL_RUN / "gcp-key.json"
```

## 4. 검증
- 옛 참조(`HERE / ".env"`, `HERE / "gcp-key.json"`) 잔재 0건, py_compile 통과(14개 .py).
- 샌드박스(레포 구조 복제 + 가짜 local.env·gcp-key.json)에서:
  backfill_usage·backfill_summary·fill_amend_type·relabel_tracks·run_migration·reanalyze_ghosts 모두
  `local_run/local.env`·`local_run/gcp-key.json`으로 해석, `_preflight()` 네트워크 없이 통과,
  reanalyze_ghosts는 GCP 키를 환경변수에 주입하고 QRADAR_SHEET→GOOGLE_SHEET_URL 보완 동작 유지,
  reanalyze_ledger/common.load_env()·start.py·pref_export 로더 동일 경로 확인.
- (2차) 시크릿 이름만 적은 local.env(GOOGLE_SHEET_URL, QRADAR_SHEET·PREF_SHEET_ID 없음)로 재검증:
  fill_amend_type·relabel_tracks(core 경로 추가 시)·backfill_usage·reanalyze_ghosts·reanalyze_ledger 통과,
  pref_export는 PREF_SHEET_ID 없이 GOOGLE_SHEET_URL을 자동 선택. backfill_summary·run_migration은 MONITOR_SHEET·RADAR_SHEET를
  더 넣었을 때만 통과(일회성 이관 도구의 원래 요구사항).
- 메일 발송 경로 점검: migrate_tool 도구는 report_maker·웹훅을 호출하지 않음(brain·config만 import) →
  통합 local.env에 WEBHOOK_URL이 있어도 도구 실행으로 메일이 나가지 않음.

## 5. 담당자 절차 (순서)
1. 수정된 migrate_tool 파일 18개를 로컬 레포의 같은 경로에 덮어쓰기.
2. `local_run/local.env`에 아래 줄만 **추가**(기존 줄 유지 — 시트 주소는 이미 있는 GOOGLE_SHEET_URL 하나로 충분):
   ```
   # ── 운영(daily.yml)과 같은 모델 설정 — reanalyze_ledger·run_today.py 모두 이 값을 읽음 ──
   LLM_MODEL=gemini-3.8-flash
   LLM_THINKING_LEVEL=medium
   # (선택) 월간 브리핑을 로컬에서 돌릴 때만
   BRIEFING_WEBHOOK_URL=
   ```
   `QRADAR_SHEET`·`PREF_SHEET_ID` 줄이 있으면 지운다(더 이상 읽지 않음). `local_run/gcp-key.json`은 이미 그 자리에 있음(서비스계정 이메일이 세 시트에 공유돼 있는지만 확인).
3. 복사본 삭제(휴지통 말고 완전 삭제): `migrate_tool/local_run/` 폴더, `migrate_tool/.env`, `migrate_tool/gcp-key.json`.
4. 확인(시트에 쓰지 않는 점검만): `python migrate_tool/reanalyze_ledger/start.py` → 경고 없이 메뉴가 뜨면 OK(0으로 종료),
   `python migrate_tool/run_migration.py` 실행 직후 사전점검 메시지 확인(미리보기 모드).
5. 열쇠 4종 교체 — 단일화 **후**에 하면 혹시 남은 옛 복사본도 자동으로 죽은 열쇠가 됨.

## 6. 영향·주의·후속
- 영향 범위: 로컬 도구만. GitHub Actions(Secrets 주입), pipeline/, navigator/는 한 줄도 바뀌지 않음.
- **run_today.py 동작 변화 1건**: 통합 local.env에 LLM_MODEL·LLM_THINKING_LEVEL을 적으면 로컬 일일 실행도
  그 모델을 쓴다(종전 로컬 실행은 값이 없어 코드 기본값 gemini-3.5-flash로 돌고 있었음) → 운영과 같은 값으로 적을 것.
- pref_export: 2차에서 GOOGLE_SHEET_URL을 1순위 후보로 넣어 PREF_SHEET_ID 없이 동작(구 시트 주소를 함께 적어도 1순위가 먼저 잡힘).
- 후속 과제(이번 범위 제외, 별도 승인 후):
  ① (2차에서 완료) 시트 변수 이름 통일.
  ② 로더 인코딩 `utf-8` → `utf-8-sig`(메모장 BOM 방어, 1단어 변경) — 현재 local.env 첫 줄이 주석이라 당장 문제는 없음.
  ③ `migrate_tool/로컬웹훅테스트 0709.py`(로컬 전용)에 웹훅 주소가 평문으로 박혀 있음 → 교체 뒤 파일 삭제 또는 주소 제거.
  ④ 루트 `_bundle/`(core 구판 스냅샷, 2026-07 기준)은 어떤 도구도 읽지 않음(reanalyze_flagged는 migrate_tool/_bundle을 기대) → 삭제 검토.

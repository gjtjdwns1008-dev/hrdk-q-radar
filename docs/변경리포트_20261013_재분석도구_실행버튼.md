## 1. 배경
- 도구 README와 start.py 는 "start.py 를 ▶ 버튼으로 실행 → [1] 대상 선정 → [2] 재분석 → [3] 시트 반영(미리보기 후 '반영' 입력 시에만 기록)" 이라고 약속한다.
- 실측(10/13, GitHub ec14564 클론) 결과 두 군데가 약속과 달랐다.
  - **[1] scan.py** — `--targets / --ids / --all` 중 하나가 필수(`required=True`)라 인자 없이 켜면 안내문만 찍고 바로 종료(오류 코드 2). start.py 는 인자를 주지 않으므로 메뉴 [1]은 항상 실패.
  - **[3] apply.py** — 인자 없이 켜면 미리보기까지만 하고 "`--commit` 을 붙여 실행하라"고 끝난다. ▶ 버튼으로는 `--commit` 을 붙일 수 없으므로 메뉴 [3]으로는 영영 반영이 안 됨.
- 작업 규칙 "모든 로컬 도구는 Python ▶ 버튼으로 명령줄 인자 없이 실행 가능해야 함" 에도 어긋난다. run.py 는 이미 인자 없을 때 화면에서 건수를 묻는 구조라 그 방식을 그대로 따랐다.

## 2. 결정
- 명령줄 사용법(README 3단계 표)은 **그대로** 둔다. 인자가 하나라도 있으면 예전과 똑같이 동작한다.
- 인자가 **하나도 없을 때(= ▶ 버튼 / start.py 메뉴)** 만 화면에서 묻는다.
- apply.py 의 기본은 여전히 **미리보기** 다. '반영' 이라는 단어를 정확히 입력한 때만 기록하고, 백업 탭 자동 생성·MST_ID 대조·검산은 그대로.

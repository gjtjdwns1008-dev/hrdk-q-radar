# 검토리포트 — 방문 통계 허브 build_stats.py (Q-PAGE 제공분) 코드 검토·수정 4건
2026-11-04 · 대상: tools/build_stats.py(121줄) + .github/workflows/stats-collect.yml(기반영) · 담당자 결정: 시점 유예 없이 진행, 파일은 검토 후 우리가 커밋, 토큰은 읽기 전용

## 1. 검토 범위와 합격 항목
- 열쇠 취급 ✅ — 토큰은 요청 머리글(Authorization)에만 실리고, 로그·원장·관제판 어디에도 쓰지 않음. 실패 시에도 오류 '종류'만 출력
- 외부 전송 ✅ — 바깥으로 나가는 요청은 goatcounter.com(두 사이트 주소)뿐. 데이터를 다른 곳으로 보내는 코드 없음
- 쓰기 범위 ✅ — stats-ledger/·stats-site/만 생성·기록(워크플로의 git add 대상과 일치)
- 멱등(같은 날 재실행) ✅ — 지난날 원장 파일이 있으면 재수집하지 않고 읽기만, 오늘분만 매번 갱신. 재실행해도 원장이 꼬이지 않음
- 실패 연성 처리 ✅ — 한 사이트 집계가 실패하면 그 사이트만 '적용 대기' 카드로 표시하고 나머지는 정상 생성
- 워크플로 정합 ✅ — 인자(qpage_live.html stats-site --ledger stats-ledger)·[skip ci]·경로 전부 일치. 호출 간 0.3초 대기는 공식 속도 제한(초당 4회) 안

## 2. 수정 4건 (★검토수정 주석으로 표시)
| # | 위치 | 내용 | 근거 |
|---|---|---|---|
| 1 | fetch_day | API limit 200→100 | 공식 문서 상한 1~100(기본 20) — 200은 요청 거절 위험. goatcounter.com/api2.html#get-/api/v0/stats/hits |
| 2 | _clean 신설 | 방문자 브라우저가 정하는 문자열(페이지 제목)에서 HTML 특수문자 제거·60자 제한 후 관제판에 사용 | 관제판이 이 값을 화면에 그대로 끼워 넣음(innerHTML) → 소독 없이는 방문자가 관제판에 악성 스크립트를 심을 수 있음(저장형 XSS) |
| 3 | 임베드 | DATA를 HTML에 넣을 때 '<'를 \u003c로 치환 | 문자열 속 '</script>'가 스크립트 블록을 끊고 임의 HTML을 여는 고전적 구멍 차단 — 방문자는 주소창 해시로 임의 문자열(path)을 기록시킬 수 있음 |
| 4 | main | Q-PAGE 화면에서 종목명 사전(qdata)을 못 찾아도 중단하지 않고 코드로 표기 | 사전 부재 시 기존 코드는 즉시 예외 → 매일 실패. 화면 개편에도 수집은 계속되도록 |
검증: 데모 렌더 2종(사전 있음/없음)·보안 단위시험(소독·치환) 통과, Q-RADAR 미개통 시 '대기' 카드 확인.

## 3. 남은 의존(콜리그 몫)
- Q-PAGE 라이브 수신(curl -f)이 실패하면 실행 전체가 실패 — 실패 허용 처리 여부는 기존 회신의 확인 1건 그대로
- GoatCounter 사이트 시간대를 Asia/Seoul로 설정했는지 확인(일별 경계가 이 설정을 따름)
- (선택) 하루 경로가 100종을 넘는 날이 오면 after 커서로 다음 쪽을 받는 보강 — 현재 규모에선 불필요

## 4. 첫 실행 기대치
Q-PAGE 섹션은 숫자가 바로 나오고, Q-RADAR 섹션은 네비게이터 집계 스니펫 반영 + 첫 방문 이후부터 숫자가 쌓임(그 전엔 0 또는 '대기'). 관제판은 Q-PAGE가 /stats로 서빙.
